semántica

El esqueleto de una página

HTML5 reemplazó el clásico <div id="header"> por etiquetas que describen su propio rol: <header>, <nav>, <main>, <article>, <aside>, <footer>. El navegador y los lectores de pantalla entienden la estructura sin depender de nombres de clase.

document.body
<header>
Título del sitio y branding. Aparece una sola vez por página (o por <article>).
<nav>
Bloque de enlaces de navegación principal. Los lectores de pantalla pueden saltar directo aquí.
<aside>
Contenido relacionado pero no esencial: barra lateral, notas, publicidad.
<main>
El contenido único de la página. Solo debe existir uno por documento.
<article>
Contenido independiente y autocontenido: un post, una noticia, una tarjeta de producto.
<footer>
Créditos, contacto o enlaces legales. Puede repetirse dentro de un <article> también.

<progress>, <meter> y <details>

Elementos de contenido nativos que antes requerían widgets hechos a mano: una barra de progreso, un medidor de rango con umbrales, y un desplegable sin JavaScript.

<progress value="70" max="100">
<meter min="0" max="100" value="82" low="40" high="80" optimum="90">
<details><summary> — ¿qué es esto?

Un acordeón nativo del navegador. No necesita JavaScript ni CSS para expandirse: el propio HTML mantiene el estado abierto/cerrado.

¿Por qué usarlo en vez de un div con onclick?

Es accesible por teclado y para lectores de pantalla desde el primer momento, y sigue funcionando si el JavaScript falla en cargar.
